## What to build

Correção dos bugs do relatório, no fluxo obrigatório: reproduzir → teste de regressão que falha (red) → correção → teste passa (green). Inclui o bug do build webpack.

**Objective:** zerar Critical e High sem introduzir regressão, deixando cobertura permanente para cada bug automatizável.
**Scope:** bugs `QA-NNN` Critical/High obrigatoriamente; Medium quando automatizável e de baixo risco; Low documenta-se.
**Preconditions:** QA-12 aprovado (relatório com repro e evidência).
**Tools:** vitest (regressão de domínio na seam `DoguinhoApp`, prior art `application.test.ts`), Playwright (regressão E2E quando o bug é de fluxo), gates do baseline.
**Execution steps:** por bug: reproduzir na branch; escrever teste que falha; corrigir; teste verde; gates (lint/typecheck/unit) verdes; atualizar o relatório com status "fixed" + link do teste. Para o build: correção provável `build: "next build --turbopack"` (ou ajuste de dependências) com verificação `npm run build` verde.
**Expected behaviour:** nenhum fix sem teste que o cubra; nenhum gate quebrado ao final.
**Evidence required:** diff do fix, saída red→green do teste, gates verdes.
**Do not do:** não corrigir silenciosamente sem teste; não refatorar além do necessário para o fix; não fechar Medium/Low sem registro.

## Acceptance criteria

- [ ] 0 Critical e 0 High abertos ao final
- [ ] Todo bug corrigido tem teste de regressão que falhava antes e passa depois
- [ ] `npm run build` verde (bug do build resolvido)
- [ ] lint/typecheck/unit verdes após os fixes
