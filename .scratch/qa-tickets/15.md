## What to build

Reteste final completo e veredito do QA Gate: lint → typecheck → unit → build → E2E → reteste dos fluxos afetados → smoke crítico em navegador.

**Objective:** provar que o sistema está pronto para o QA manual humano.
**Scope:** todos os gates do BASELINE + suíte E2E + passada rápida nos fluxos críticos (login, Fechamento, Correção, Estoque, gestão de usuário).
**Preconditions:** QA-14.
**Tools:** gates npm, Playwright, navegador para smoke.
**Execution steps:** rodar cada gate e registrar resultado; rodar E2E; refazer manualmente (browser) os fluxos críticos; comparar com o BASELINE (nenhuma regressão inexplicada); avaliar o gate: 0 Critical, 0 High, fluxos críticos verdes, regressão verde, build verde, Medium/Low documentados; atualizar `QA_REPORT.md` com o veredito final.
**Expected behaviour:** gate passa ou a lista de bloqueadores é explícita.
**Evidence required:** saída de cada comando, veredito do gate no relatório.
**Do not do:** não declarar gate aprovado com High aberto "só mais esse"; não pular o smoke manual.

## Acceptance criteria

- [ ] Todos os gates executados e registrados (tabela final no relatório)
- [ ] E2E verde
- [ ] Smoke crítico manual feito com evidência
- [ ] Veredito do QA Gate registrado: PASS ou bloqueadores explícitos
