## What to build

Execução dos cenários de Perfis e Usuários: CRUD de Perfil via checklist, ciclo de vida do usuário, invariantes do último Dono, e efeito imediato de mudanças de acesso.

**Objective:** provar que gestão de acesso funciona e que as invariantes de Dono protegem a Organização.
**Scope:** `/perfis`, `/usuarios`.
**Preconditions:** QA-02; Dono; segundo Dono (`dono2`) para testar rebaixa.
**Identity / Role:** Dono; usuário alvo dos testes de desligamento.
**Tools:** Playwright com 2 contexts (Dono + usuário logado que será desligado).
**Execution steps:** criar Perfil com subconjunto de permissões; nome duplicado → conflito; editar Perfil muda permissões de quem usa (verificar no próximo request do usuário afetado); excluir Perfil livre → ok; excluir Perfil em uso → bloqueado; criar usuário: senha <8 → erro, e-mail sem `@` → erro, e-mail duplicado → conflito, Perfil inexistente (forçado) → erro, Loja inexistente no Vínculo (forçada) → erro; desligar usuário logado → sessão dele morre na próxima navegação; desligar/rebaixar último Dono → bloqueado; com 2 Donos, rebaixar um → permitido; alterar Vínculo reflete imediatamente nas Lojas visíveis.
**Expected behaviour:** conforme `app.criarPerfil/editarPerfil/excluirPerfil/criarUsuario/desligarUsuario/rebaixarDono/alterarVinculo/alterarPerfilUsuario`.
**Evidence required:** screenshots, mensagens exatas, prova de sessão revogada (context do usuário desligado).
**Do not do:** não deixar o ambiente sem Dono ao final do cenário; não usar contas de outros cenários sem documentar.

## Acceptance criteria

- [ ] CRUD de Perfil com vereditos, incl. "em uso" bloqueado
- [ ] Criação de usuário valida senha≥8, e-mail, Perfil e Lojas do Vínculo
- [ ] Desligar revoga sessão ao vivo (prova com 2 contexts)
- [ ] Último Dono protegido (desligar e rebaixar); rebaixa possível com 2 Donos
- [ ] Mudança de Perfil/Vínculo tem efeito imediato verificado
