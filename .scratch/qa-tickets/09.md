## What to build

Execução dos cenários de Dashboard e Estoque: KPIs corretos, lista de Lojas sem Fechamento hoje, recorte por Vínculo e status por Loja.

**Objective:** provar que o Dashboard conta a verdade operacional e respeita o Vínculo.
**Scope:** `/dashboard`, `/estoque`.
**Preconditions:** QA-05 (há ao menos uma Loja com Fechamento hoje e outra sem).
**Identity / Role:** Dono (vê todas); `operador.centro` (vê só Centro); `restrito` (sem `dashboard` → acesso à página negado).
**Tools:** Playwright.
**Execution steps:** como Dono: KPIs batem com os dados criados (Lojas com/sem Fechamento, recentes ≤20); "sem Fechamento hoje" lista exatamente as Lojas sem envio; como `operador.centro`: Dashboard mostra só Centro; `/estoque` status corretos (`nunca_fechou`/`rascunho`/`enviado`); como `restrito` (sem permissão `dashboard`): `/dashboard` negado; Estoque visível (tem `read_estoque`).
**Expected behaviour:** conforme `app.dashboard` (recorte por Vínculo, recentes limitado a 20) e `estoqueDaLoja`.
**Evidence required:** screenshots com os dados de controle anotados, tabela esperado × exibido.
**Do not do:** não assumir KPI — calcular o esperado a partir dos dados criados nos cenários anteriores.

## Acceptance criteria

- [ ] KPIs conferem com dados de controle criados no QA
- [ ] "Sem Fechamento hoje" exato
- [ ] Recorte por Vínculo verificado (operador não vê Magalhães)
- [ ] Sem permissão `dashboard`, página negada com evidência
